# 【阶段7】最简UI与稳定性测试

日期：2026-10-02。已达到本机演示范围的阶段7验收标准。冻结版本和`v0.1-demo`标签在阶段8执行。

## 完成内容

- 新增本机浏览器界面和双击启动入口，支持项目名称、自由自然语言、明确模板确认、解析参数及原文依据、三个执行步骤、工具调用日志、设计摘要、校核警告、CAD状态和打开图纸。
- 界面后台复用已有Controller、Registry、Tool和Project State。SQLite运行状态为依据；每次提交生成独立项目/运行记录，刷新和服务重启可以读取历史。
- 单次任务串行执行；禁止执行中重复提交、打开历史图纸、恢复或退出。缺参和失败停止后续工具，不自动重试。恢复入口仅处理既有工具归属会话。
- 默认只监听127.0.0.1；页面API使用本机会话及来源校验；静态文件白名单、受控DWG打开及输入长度限制，无新增依赖。
- 通过界面连续执行A/B/C两轮。统一项目名称字段后，完整旧引擎结果及CAD场景哈希均与原冻结基线一致；冻结基线未改动。

## 发现的问题

- 开发沙箱内后台进程无法访问API，界面正确停止；改由正常本机后台程序运行，真实链路通过。该失败记录保留，没有自动重试。
- 恢复线程启动失败可能留下忙碌状态，已补齐清理和测试。
- 新项目名称导致未经规范化的设计/图纸哈希不同；已核对差异仅为标题，验收规范化名称而不更新冻结基线或计算公式。

## 技术债务

AutoCAD硬挂起、许可/信任等全部模态组合、CAD进程崩溃/断电、第二台物理设备，以及真实云鉴权/余额/限流/5xx故障仍未完整验收。模拟故障测试只证明界面和工作流的失败处理，不能关闭这些实机边界。详情见[技术债清单](../technical-debt.md)。

UI目前为楼盖演示提供案例和摘要，未来专业可增加呈现描述。跨设备共享运行状态、多人CAD调度与工作流中间续跑保持后续范围。
