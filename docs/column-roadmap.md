# 柱插件阶段路线与模型协作

用户于2026-10-07确认本路线，选择阶段16优先交付柱网页与结果展示。阶段15已有教学非抗震、静力、理想纯轴压设计与实配校核；后续阶段的规划不代表功能已实现或已通过验收。各阶段实况以对应阶段报告及PR为准。

## 模型职责

| 模型 | 设置 | 职责 |
| --- | --- | --- |
| GPT-6.1 Sol | `gpt-6.1-sol`，`high` | 审计、接口、实现、测试、修复、文档与Git交付 |
| GPT-6 Astra | `gpt-6-astra`，`xhigh` | 只读工程依据、独立算例、接口和代码审查，提供位置、影响和验证方法 |
| DeepSeek | 现有云解析配置 | 后续自然语言参数提取及澄清，不承担确定性计算、配筋判定或未经授权的改参 |
| DeepSeek Harness开发子Agent | 独立`sdk-minimal`、默认`deepseek-flash` | 可选文档、测试、范围明确的小模块实现；GPT审核补丁与验证后整合，不代替Astra工程审查，见[接入说明](dsh-development.md) |

开发顺序为Sol提交指定版本、Astra只读审查、Sol修复、Astra复核受影响部分。同一工作区不同时写入。算法阶段设置计算依据/参考算例、纯计算模块、PR交付三个审查点；界面阶段对应输入契约、功能实现、最终交付。交接包含支持范围、规范来源、参考算例、提交编号、测试结果及未解决事项。模型意见不能替代规范或工程师审定。

| 22 | 双向偏压及构造补齐 | 两方向内力和钢筋位置一致；逐项增加环境保护层、锚固搭接、节点端部，分别标明覆盖范围 |
| 23 | 柱报告、CAD Adapter及自然语言 | 读取同一有效设计引用；图文与实际配筋一致；云输出经Schema及原文证据校验，缺参先澄清 |
| 24 | 抗剪、抗震及整体分析扩展 | 分别先锁定工程范围、条款和参考，再实施；优先Adapter接入经验证的整体分析程序 |

阶段20是上游独立路线，可在阶段17后推进；阶段21等待柱与上游分析均通过相关验收。阶段20首版不包含板上墙的传力、承重墙支承刚度或剪力墙共同受力。柱PASS不能代替整条楼盖—柱链的工程结论。

## 接口与版本规则

- 工具沿用Envelope、EngineeringTool和ToolResult；专业实现与呈现在插件内，Controller不导入具体算法。
- 输入范围通过本地Schema和工程验证表达，不能只放宽Schema开启未经验证的算法。
- 设计与实配校核保持分离，保存不可覆盖且核对归属的引用；新阶段不能覆盖历史失败记录。
- 旧楼盖计算、LISP、阶段15独立参考及`v0.1-demo`冻结标签保持原基线。
- 每阶段独立分支/PR，核对上游依赖状态，不自动合并。公开仓库只包含源码、匿名案例、测试和说明，不包含密钥、验证日志或真实工程数据。
- 新阶段完成后更新技术债和阶段报告。实现、自动测试、实机/人工验收分别记录，缺证据不标记通过。
