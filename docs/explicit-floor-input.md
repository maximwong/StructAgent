# 完整工程参数模式（v0.2开发版）

此功能在`feature/explicit-floor-input`开发；`v0.1-demo`标签和Release保持冻结。它解决必须勾选办公楼模板才能开始设计的问题，不扩展旧引擎的结构适用范围。

## 界面使用

1. 配置本机DeepSeek，打开空闲的AutoCAD 2022。退出此前启动的StructAgent服务，再从本分支启动`app.py`；旧进程不会自动加载新代码。
2. 将“工程参数来源”切换为“完整工程参数（不使用模板）”。本模式不要求模板复选框。
3. 展开分组，填写全部参数或导入完整模型JSON。也可主动点击“载入已验证案例作为起点”，再修改；不点击不会自动带入案例数值。
4. 填写自然语言，例如“按工程参数表设计并出图。”表单内的跨度、材料和荷载不必在文字中重复。
5. 点击开始。缺项显示具体字段，补齐表单后再次开始；缺项不会调用云模型、设计或CAD工具。每次开始创建新运行，不续跑旧CAD步骤。

参数表从现有Schema生成，共70个字段，分组展示。数组用逗号分隔；几何长度mm、容重kN/m³、活荷载kN/m²、强度MPa，比例/系数无量纲。JSON为完整模型本身，不含Envelope、`input_mode`或`template_id`。可导入`legacy/rc_floor/demo_a.json`或`legacy/rc_floor/changed.json`；上传限12KB，未知字段拒绝导入。

界面“项目名称”标识并隔离一次运行；参数中的“工程显示名称”用于图纸标题。历史保留原始表单、文字、解析后的有效模型及来源，刷新恢复原输入。结果参数表可滚动查看。

材料等级与强度须一致。表单手动选择C35时，也须填写fc=16.7、ft=1.57；其他等级见既有材料校验模块。自然语言明确改变混凝土等级时，插件按同一既有映射更新fc/ft并记录来源。冲突的原始表单先被拒绝，不静默改值。梁纵筋HRB400、板筋及箍筋HPB300仍是支持范围。

## 自然语言修改

支持13项修改：主梁/次梁各轴跨、混凝土等级、梁纵筋等级、活荷载、板厚、次梁宽/高、主梁宽/高、次梁间距、面层厚度、抹灰厚度。其余参数可直接编辑表单；文字要求改变保护层、容重、支承、配筋或构造等时，需要澄清并在表单修改，不能忽略。

```text
麻烦板厚改成100mm，次梁截面225×450mm，主梁截面300×650mm，活载改2.8kN/m²，其余按表单设计。
```

截面按宽×高。模型返回修改值、逐字原文依据和澄清事项，本地校验数值与单位、材料映射及完整模型后送既有Tool。原始表单不发送给DeepSeek，自然语言文字仍通过云API解析。没有单位的“次梁250×500”会请求补充单位，不能猜毫米。

轴跨修改作用于原数组的全部3/5跨，不会连带修改间距或截面。主梁改为5.4m而间距仍为2000mm时，可能被旧引擎的三分点规则拒绝；应同时明确填写1800mm间距。`ready`表示解析契约通过，工程计算仍可拒绝不适用输入。

## 命令行

在仓库根目录执行以下完整一行，可换成自己的完整模型文件：

```powershell
.\.venv-demo\Scripts\python.exe -m examples.agent_workflow --model-file .\legacy\rc_floor\demo_a.json --text "板厚改100mm，其余按工程参数表设计并出图。"
```

`--model-file`与`--template`互斥。不提供任何模式仍不会猜模板。此命令实际调用DeepSeek、计算与CAD；`--status <run_id>`只读历史。

## 范围

这一步提供完整输入和表单缺参交互，尚未提供一句话补齐全部字段或多轮对话自动合并状态。完整表单缺项先停止解析，不能靠同次文字填齐缺失模型。任意跨数、布置及其他结构能力仍需扩展和验证旧引擎。

插件负责Schema、表单描述与语言编辑契约。后续阶段已在插件工作流中接入独立`check_floor_design`，Controller、设计/CAD Tool、Adapter及旧计算/LISP仍未改动；见[校核说明](floor-check-tool.md)。尚未完成v0.2自主改参闭环。

本机验收包括修改后完整模型的两次真实出图；公共CI模拟云/CAD，计算仍真实。见[阶段报告](stages/phase-9.md)。
