# 网页计算书操作

阶段13在既有本机页面增加“计算书”卡片，用户选择最近一次设计后，显式点击生成、打开或下载。普通设计仍按parse→design→check→CAD执行，报告不是开始设计的额外必选项。

## 使用与验收

1. 更新到`feature/report-ui`，空闲时退出旧程序，再用原启动文件或固定环境运行`app.py`。页面默认仍为`http://127.0.0.1:8765/`。
2. 完成一次设计，或在“最近运行”选择已有记录。设计和独立校核通过、结果引用完整时，“生成计算书”启用。旧版本没有Check的记录不补造通过状态；CAD未开启导致的普通失败可以生成报告，待恢复或仍运行的任务不允许操作。
3. 点击“生成计算书”。页面显示只读校核和报告生成状态，过程中禁止重复提交、打开文档、恢复CAD及退出。报告不调用云模型，不重新设计或出图，因此这一步不需要API服务在线。
4. 完成后显示Word格式、图表数量、校核汇总和独立报告运行编号；可点击“打开计算书”使用本机文件关联，或“下载计算书”保存DOCX到浏览器下载目录。目录和页码可在Word中选择全文并按F9更新。
5. 刷新页面、重启服务后仍能读取已完成报告，原设计状态不改变。“重新生成计算书”建立新的报告与运行编号，旧文件保留；当前页面展示最近一次报告。

手动验收：检查真实文档软件是否打开指定DOCX，下载文件能否读取、内容和校核是否对应原设计；再次生成、刷新页面后确认原设计和原文件保留。浏览器下载反馈仅表示已交给浏览器，不保证用户已完成保存。

修改保存报告原件后，其内容已不再匹配生成回执，页面会停止打开/下载；如需保留编辑稿，另存副本。重新生成得到新的完整报告，不覆盖编辑稿。计算书不代表全项工程规范审查通过。

## 实现与归属

应用组合层注入报告Controller工厂、专业源记录验证器和产物验证器。UI报告服务只管理操作与持久记录，Controller不导入专业脚本；专业报告验证在`tools/floor/report_presentation.py`。

报告使用独立`artifact_report`工作流，通过同一Registry调用`generate_floor_report`。请求由已保存Design/Check推导，HTTP不接受设计引用、路径或工程修改参数。原UI任务记录绑定原设计run_id，防止同项目新增报告后将报告误当设计状态。原SQL终态与Design/Check/CAD文件不改写。

每次请求保存在`ui/report-jobs/<原任务>/<报告请求>.json`，报告产物仍由阶段12Tool保存。完成必须有匹配的COMPLETED项目状态、单个报告ToolResult、源设计哈希、文件回执、完整DOCX包与计数；重新核对校核依据及生成文件SHA256。坏路径、跨项目、空文件、损坏回执、缺失/已归档的源结果都停止文件操作。报告生成失败不改变原设计结果；完整文件但报告关联发布失败仍不可下载。

生成和打开接口沿用本机Host、Origin及会话令牌；下载也需要会话令牌，通过带鉴权fetch获取附件，不使用含令牌的URL，也不暴露任意文件浏览。下载正文是已校验的同一字节副本；打开文件在调用本机文件关联前重新验证。

## 限制

当前网页只为普通楼盖设计记录生成报告，受限调整记录附录继续用阶段12显式CLI，尚无网页尺寸授权或调整记录选择。正式PDF、失败产物自动清理和历史报告选择器未接入；此前文件与运行记录保留。中断的报告请求不会自动续跑或认定完成，需检查后重新生成。

正常工程计算及DOCX生成采用真实工具；自动HTTP/UI测试中的CAD与云解析为明确模拟。报告正文和样式未修改，不重复计作阶段12的123页版面验收。浏览器实际显示、下载落盘和文档软件关联的状态分别记录在[阶段13报告](stages/phase-13.md)，不能用HTTP响应成功代替实机下载证据。
